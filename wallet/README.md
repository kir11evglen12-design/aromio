# COBALT — криптокошелёк

Демонстрационный кошелёк в духе расширения-кошелька: две очень большие
кнопки **«Купить»** и **«Продать»** на главном экране, сине-чёрная тема,
живые (сгенерированные) котировки.

Открывается двойным щелчком по `wallet/index.html` — сборка не нужна.

```
wallet/
├── index.html      разметка-оболочка: рамка «устройства» и порядок скриптов
├── styles.css      токены палитры и все компоненты
├── wordlist.js     256 слов, из которых собирается демо-фраза
├── qr.js           кодировщик QR (byte-режим, уровень M, версии 1–10)
├── vault.js        SHA-256, base58, адреса, пароль, шифрование фразы
├── market.js       токены, ценовые ряды, тики, форматирование денег
├── wallet.js       счета, балансы, история и операции над ними
├── ui.js           DOM-хелперы, иконки, графики, шторки, тосты
├── screens.js      все экраны и шторки
├── app.js          роутер, запуск, тики рынка
└── tests/          прогоняются одной командой: node wallet/tests/run.cjs
```

## Почему без сборки и без фреймворка

Витрина Aromio собирается Vite в один файл; кошелёк — отдельное приложение,
и ему нечего добавить в тот бандл. Обычные `<script>` без модулей дают
главное свойство: файл работает и с `file://`, и с GitHub Pages, и внутри
превью — без сервера и без шага сборки. Экранов девять, состояние одно,
поэтому перерисовка «создать узел заново» читается лучше любого diff-слоя.

## Что умеет

| Экран | Что там |
|-------|---------|
| Приветствие | создание кошелька или восстановление по фразе |
| Создание | пароль → 12 слов под размытием → проверка трёх слов наугад |
| Блокировка | вход по паролю, сброс кошелька |
| Главный | общий баланс, суточное изменение, **КУПИТЬ / ПРОДАТЬ**, отправить / получить / обмен / история, вкладки «Токены · Коллекции · История» |
| Токен | график с шестью таймфреймами и курсором, доля портфеля, комиссия сети |
| Купить | карта, выбор токена, клавиатура, быстрые суммы, курс и комиссия, подтверждение удержанием |
| Продать | доли 25/50/75/100 %, расчёт выплаты на карту |
| Отправить | адрес с проверкой base58, комиссия сети, остаток |
| Получить | настоящий QR-код адреса и копирование |
| Обмен | пара токенов, курс, влияние на цену, комиссия 0,25 % |
| Настройки | валюта (₽ / $ / €), скрытие сумм, показ фразы по паролю, блокировка, сброс |

Мелочи, которые делают ощущение кошелька: подтверждение денежных операций
удержанием кнопки (а не случайным тапом), тики цен каждые 2,6 с с обновлением
только чисел (скролл не прыгает), пауза рынка в фоновой вкладке, работа с
физической клавиатуры, `prefers-reduced-motion`, полноэкранный режим на телефоне.

## Карта: почему «Купить» и «Продать» симметричны

К кошельку привязана демо-карта с 5 000 $. Покупка списывает с неё, продажа
возвращает на неё. Без этого «купить» просто печатало бы деньги из воздуха,
а кнопка «Макс» не имела бы смысла.

Комиссии: покупка и продажа — 1,2 %, обмен — 0,25 %, перевод — сеть по
эквиваленту 0,12 $. Тест проверяет, что покупка и обратная продажа той же
суммы стоят ровно две комиссии и ничего сверх того.

## Криптография: что она даёт и чего не даёт

`vault.js` не использует WebCrypto — тогда приложение вело бы себя по-разному
с сервера и с диска. Внутри собственный SHA-256, и на нём:

* пароль **не хранится** — только соль и 20 000 раундов SHA-256 от него;
* секретная фраза лежит в localStorage, зашифрованная гаммой (SHA-256 в режиме
  счётчика) на ключе из этого же пароля;
* адрес счёта — base58 от `sha256("cobalt/account/<i>/<фраза>")`, поэтому
  один и тот же набор слов всегда даёт те же адреса.

Честно про границы: 20 000 раундов SHA-256 на JS — это не scrypt и не Argon2,
а самодельная поточная гамма — не AES-GCM. Для симулятора этого достаточно,
для настоящих ключей — нет, и переносить `vault.js` в такой проект нельзя.

## Почему свой QR, а не библиотека

Экрану «Получить» нужен код, который читает камера телефона, поэтому в
`qr.js` лежит настоящий алгоритм ISO/IEC 18004: Рид—Соломон над GF(256),
служебные шаблоны, восемь масок с оценкой по штрафным правилам. Проверялся он
так:

* матрицы сравнены побайтово с эталонным кодировщиком **segno** — версии 1–10,
  все восемь масок, полезная нагрузка ровно по ёмкости (80 из 80 совпали);
* выбор маски совпадает с segno на тех же данных;
* готовые коды прочитаны декодером **OpenCV**, включая скриншот самого
  интерфейса — из картинки экрана вынулся ровно адрес счёта.

Фиксированные матрицы сложены в `tests/qr.golden.json`, чтобы правки в
кодировщике не сломали его молча.

## Данные

Всё лежит в `localStorage` под ключом `cobalt.wallet.v1` и никуда не уходит:
сетевых запросов в приложении нет вообще. Котировки — сид-генерируемые
случайные блуждания: график за «1Д» после перезагрузки тот же самый, а
процент на строке считается по тому же ряду, который нарисован.

При создании кошелька начисляется демо-портфель (≈ 18 000 $) и несколько
прошлых операций — иначе первый экран был бы пустым.

## Про безопасность пользователя

Это симулятор, и он об этом говорит: значок «демо» в шапке, предупреждение на
экране «Получить», отдельное предупреждение при восстановлении. Экран импорта
принимает **только** слова из своего словаря — настоящая seed-фраза от
реального кошелька будет отвергнута с объяснением. Настоящий кошелёк никогда
не просит секретную фразу ни в переписке, ни на сайте.

## Тесты

```bash
node wallet/tests/run.cjs
```

Три набора, без зависимостей:

* `qr.test.cjs` — эталонные матрицы, структура символа, границы версий;
* `vault.test.cjs` — SHA-256 против `crypto` из Node на длинах 0…200 и юникоде,
  base58 против BigInt-реализации, фразы, адреса, пароли, шифрование;
* `store.test.cjs` — арифметика покупки, продажи, перевода и обмена, комиссии,
  сообщения об ошибках, счета, блокировка и восстановление состояния.

Отдельно интерфейс прогонялся Playwright по всему пути (создание → покупка →
продажа → перевод → обмен → блокировка → перезагрузка) без единой ошибки в
консоли и без горизонтального скролла на 390 px.
