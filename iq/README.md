# ИНДЕКС — тест IQ

Отдельное приложение: страница, которая даёт 36 заданий, считает балл по
шкале со средним 100 и разбросом 15 и показывает разбор каждого задания.
К витрине AROMIO отношения не имеет — обычные `<script>` без модулей,
открывается прямо файлом `iq/index.html`, а `iq/index-single.html` — то же
самое одним файлом.

Цена по умолчанию — **129 ₽**: пробные шесть заданий бесплатно, полный
тест по коду доступа.

```bash
node iq/build-single.cjs     # собрать один файл + docs/iq/ для GitHub Pages
node iq/keygen.cjs 20        # выпустить 20 кодов доступа
node iq/tests/run.cjs        # проверки (npm run test:iq)
```

## Что нужно сделать перед первой продажей

Всё в одном файле — `iq/config.js`:

| Поле | Зачем |
|------|-------|
| `price` | цена, ей же подписаны кнопки |
| `payUrl` | ссылка на оплату: форма ЮMoney, Т-Банка, ЮKassa — любая |
| `contact` | куда написать за кодом |
| `secret` | из него считается контрольная часть кодов — **обязательно поменять** |
| `minutesFull`, `minutesDemo` | время на полный тест и на пробную часть |

Пока `payUrl` пустой, на странице оплаты стоит не кнопка, а прямая строка о
том, что оплата не настроена: лучше так, чем мёртвая кнопка у покупателя.

Порядок продажи получается такой: человек проходит шесть заданий бесплатно,
видит предварительную оценку с широким интервалом, платит по ссылке,
получает от вас код из `keygen.cjs` и вводит его на странице. Доступ
остаётся в браузере покупателя.

## Про коды: что они делают и чего не делают

Код — это 12 знаков, из которых 8 — тело (первые два хранят номер партии),
а 4 — контрольная часть от секрета продавца. Страница проверяет код сама,
без сервера.

**Это защита от пересылки кода другу, а не от того, кто умеет читать
JavaScript.** Алгоритм лежит в исходнике страницы: человек, который его
откроет, сможет выпустить себе код. Пока продажи небольшие, это разумный
размен — никакого сервера, никаких платежей за хостинг, страница работает
даже с флешки.

Когда захочется закрыть и эту дыру, порядок такой:

1. поднять маленькую службу, которая принимает вебхук от платёжного
   сервиса и выпускает код на своей стороне;
2. заменить в `app.js` локальную проверку на запрос к ней;
3. гасить код после первой активации — тогда один код будет открывать
   доступ ровно один раз.

Ломается при этом ровно одно место — функция проверки кода; всё остальное
(задания, подсчёт, разбор) к этому не привязано.

## Как считается балл

Считать «сколько верно из 36» и называть это интеллектом нечестно: задания
разной сложности. Здесь работает обычная для тестирования модель с тремя
параметрами (3PL):

```
p(верно | способность) = 0.2 + 0.8 / (1 + exp(-1.7 · (способность − сложность)))
```

Сложность каждого задания выводится из его `p` — доли людей, которые
решают его верно (вместе с угадавшими). 0.2 — это шанс угадать один
вариант из пяти.

Способность оценивается байесовски: апостериорное среднее при априорном
распределении N(0, 1). Обычный подбор «при какой способности ответы
вероятнее всего» здесь не годится — на краях он уходит в бесконечность, а
разброс оценок получается 20 пунктов вместо 15. Из того же апостериорного
распределения берётся и погрешность, поэтому рядом с баллом всегда стоит
интервал, а не только точка.

Проверка калибровки идёт в `tests/score.test.cjs`: там моделируются 500
человек с распределением способностей N(0, 1), и проверяется, что шкала
возвращает среднее около 100, разброс около 15, несмещённую оценку и
интервал, который накрывает истину примерно в 95 случаях из 100.

### Чего эта математика не делает

Сложности заданий взяты из оценок, а не из замеров на выборке населения.
Значит балл — обоснованная оценка, а не официальный результат, и на
странице это написано прямо, а не мелким шрифтом внизу. Обещать
покупателю клиническую диагностику за 129 ₽ нельзя; обещать честно
посчитанную оценку с указанной погрешностью — можно.

## Задания

36 заданий в пяти блоках, внутри блока — от простых к сложным:

| Блок | Сколько | О чём |
|------|---------|-------|
| Числовые ряды | 8 | закономерность в последовательности |
| Слова и смысл | 7 | аналогии, классификация, вывод из условия |
| Матрицы | 8 | невербальная логика: правило спрятано в фигурах |
| Пространство | 5 | объём, повороты, счёт по рисунку |
| Логика и счёт | 8 | задачи, где первый ответ обычно неверный |

Матрицы заданы **правилом**, а не девятью нарисованными клетками:
`rule(строка, столбец)` выдаёт спецификацию клетки, а картинка рисуется из
неё. Правильный вариант ответа — это то, что правило выдаёт для закрытой
клетки, и проверка `tests/tasks.test.cjs` это сверяет. Поэтому ответ и
картинка не могут разойтись — а это ровно та ошибка, которую первым
заметил бы покупатель.

Так же проверяются и счётные задания: количество кубиков в ответе
сверяется с тем, сколько их нарисовано, а в задании на поворот
проверяется, что верный вариант — действительно поворот образца, а
остальные четыре — зеркальные копии, которые никаким поворотом не
совместить.

## Что лежит в файлах

```
iq/
├── index.html        каркас страницы и витрина
├── styles.css        тёмно-синяя матовая тема
├── config.js         настройки продавца — единственный файл для правки
├── figures.js        отрисовка фигур и геометрия полимино
├── tasks.js          36 заданий, правила матриц, объяснения
├── score.js          модель, оценка способности, интервал, разбор по блокам
├── access.js         выпуск и проверка кодов доступа
├── app.js            ход теста: витрина, задания, оплата, результат
├── build-single.cjs  сборка в один файл и в docs/iq/
├── keygen.cjs        выпуск кодов
└── tests/            проверки, чистый Node без зависимостей
```

Ответы никуда не отправляются: тест считает в браузере, состояние лежит в
`localStorage` этого же браузера.
